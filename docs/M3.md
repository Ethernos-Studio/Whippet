# Whippet M3：内部汇编器、COFF 与 O1

> 作者：dhjs0000
>
> 对应实现：`src/emit/coff.c`、`src/mid/passes.c`、`src/cli/main.c`。
> M3 验收：编译速度 ≥ 20k 行/秒（§9.1）；本仓库 20k 指令压力文件经
> `-c` 直出 COFF 约 40k 行/秒（本机，单线程）。

## 1. 范围

M3 增加两件事：

1. **内部汇编器 + COFF 直写**：不再必须调用 clang/GNU as；
2. **O1 核心 pass**：常量折叠/传播、copy/select 传播、死代码消除、
   2 的幂乘法强度削减。

仍不在 M3 范围：空块消除、不可达块删除（见 §7）、O2/GVN、数据段/全局变量、
`.pdata`/unwind、调试信息、栈探测、可变参数、浮点（M4）。

## 2. 内部汇编器

M1/M2 的指令选择仍然生成便于阅读的 GNU as 文本（`-S`）。`-c` 路径在内存中
拿到同一份文本，由内部汇编器解析并编码，因此两条路径共享所有指令选择与
寄存器分配逻辑，避免维护第二套 codegen。

```text
.wir -> parser/validator -> O1 -> isel/regalloc -> GNU as text
                                                    |-> -S (text)
                                                    |-> internal assembler -> COFF (.obj)
```

支持的指令形式就是后端实际发出的子集：

- `mov`（r/r、r/imm、r/m、m/r，8/16/32/64 位，`[rsp+disp]`/`[rcx]`）；
- `movzx`/`movsx`/`movsxd`；
- `add/sub/and/or/xor/cmp`（r/r、r/imm），`test`；
- `shl/shr/sar`（按 CL），`neg/not`，`imul`，`idiv/div`，`cqo`；
- `setcc`（al），`cmovne`；
- `lea`（`[rsp+disp]`）；
- `push/pop`，`jmp/je/jne`，`call`（直接/`rax`），`ret`。

如果未来指令选择新增形式，内部汇编器会给出明确错误，而不是静默生成错误
字节。当前它只接受自己后端产出的固定格式，不是通用 GNU as 替代品。

## 3. COFF 对象

`-c` 输出 Windows x64 COFF：

- 一个 `.text` 段，`IMAGE_SCN_CNT_CODE | MEM_EXECUTE | MEM_READ`；
- 函数符号：全局函数为 external/function，值和段内偏移正确；
- 外部调用（如 `putchar`）生成 undefined symbol + `IMAGE_REL_AMD64_REL32`
  重定位；同一对象内已定义函数的调用在内部解析为相对位移；
- 支持长符号名（string table）；
- 时间戳为 0，输出确定；
- 不生成 `.pdata`/unwind、`.rdata`、重定位以外的数据段。

已验证：所有 M2 用例和示例经 `whippet -c` 生成 `.obj`、clang 链接 C driver
后运行结果与 `-S` 路径一致；包含递归、6 参数、外部 `putchar`、间接调用、
alloca/load/store 和 i8/i16/i32/i64 宽度。

### 用法

```console
$ whippet -c -o add_mul.obj tests/cases/basic.wir
$ clang driver.c add_mul.obj -o test.exe
```

不指定 `-o` 时对象写到 stdout（Windows 下 stdout 切到二进制模式）。

## 4. O1 pass

`whippet_optimize_module(module, 1, diag)` 在 IR 上原地运行，CLI 默认 `-O1`；
`-O0` 关闭。pass 由 `src/mid/passes.c` 实现：

| pass | 内容 |
| --- | --- |
| 常量折叠/传播 | 整数 add/sub/mul/div/rem/and/or/xor/shift/neg/not、icmp、整数 cast；把结果替换到所有 use（含 phi incoming） |
| copy/select 传播 | `copy %x` 和常量条件 `select` 直接替换 use 并删除 |
| DCE | 无 use 的纯指令（算术、icmp、phi、copy、select、cast、alloca、ptradd）删除；load/store/call 保留 |
| 强度削减 | `mul x, 2^k` → `shl x, k`（k < 位宽） |

约束：

- 不折叠除零、`INT64_MIN / -1`；
- 移位量 ≥ 位宽不折叠；
- 不折叠 phi（循环携带值可能由 back-edge 定义，不能安全替换）；
- 每条删除前先替换所有 use，保持 SSA/后端可用；
- O1 跑两轮 `constant -> strength -> DCE`，DCE 内部迭代到不动点。

## 5. 测试

`ctest` 新增：

- `opt_pipeline`：常量折叠、copy 传播、DCE、强度削减、优化后 IR 仍可
  canonical round-trip；
- `obj_add_mul`、`obj_sum_to`、`obj_m2_calls`、`obj_m2_memory`：`-c` 生成
  COFF、链接 C driver、运行；其中 `obj_sum_to` 覆盖 phi/循环边，
  `obj_m2_calls` 覆盖递归、栈参数、间接调用、外部 CRT 调用和长符号名；
- 既有 `asm_*`、`examples`、`asm_differential` 现在默认走 O1，继续通过；
  `cli_emit` 用 `-O0` 固定 canonical 输出。

## 6. 速度

压力文件：单函数 20,000 条顺序 `add` 指令（约 600 KB `.wir`），本机
Windows x64/Clang Release（实际为 `-O0` 编译的 host）：

| 路径 | 时间 | 吞吐 |
| --- | --- | --- |
| `-S`（文本） | ~180 ms | ~110k 行/秒 |
| `-c`（O1 + COFF） | ~500 ms | ~40k 行/秒 |

均高于 M3 的 20k 行/秒目标。`-c` 的主要额外成本是“生成文本再解析”；
M3 后续可直接从结构化指令流发射，减少这一层。

可复现：

```console
$ python tools/bench_compile.py --whippet build/whippet.exe --instructions 20000
```

## 7. 与完整 M3 的差距

设计文档的 O1 还包含“空块消除 + 不可达块删除”。本版本先完成
常量/copy/DCE/强度削减和内部汇编器/COFF；块清理尚未启用，因为块删除会
牵动 block id、phi incoming 和活跃性数组，计划在下一轮补齐。

此外：

- 删除指令后 value 表未压缩；pass 会把结果标为 `void`，分配器跳过这些值，
  因此它们不再占用寄存器/栈槽；
- 内部汇编器通过文本往返，尚未做到 codegen 直出字节；
- 无 `.pdata`，异常/unwind 仍不可用；
- 无 O2/GVN、无数据段/全局变量。

这些不影响当前整数/指针 ABI 的正确性，但会影响大函数的帧占用和后续
浮点/异常支持。
